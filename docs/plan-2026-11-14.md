# P0 — schimbă semnul rezultatului

## P0.1 Decuplează banda de ATR(15m)

**De ce:** audit §3. `halfRange = 1.6 × ATR(15m) ≈ 1 %` produce un stop la ~2 × ATR(15m), adică
prima atingere în ~38 min; durata mediană măsurată e 50 min. Intrarea așteaptă un fill la 171 min
(`minCrossingsPerHour = 0.35`), ieșirea închide la 50 min. Contradicție prin construcție.

**Ce se schimbă:**
- `src/server/engine/grid/gridPlan.ts` — `deriveGridGeometry` primește un orizont de holding țintă
  (`targetHoldingHours`, implicit 8) și o sursă de ATR pe orizont lung (`atrPct1h`).
  `halfRangePct = clamp(k × ATR(1h) × √targetHoldingHours, GRID_MIN_HALF_RANGE_PCT_HOLD, 6)`,
  cu `GRID_MIN_HALF_RANGE_PCT_HOLD ≥ 2.0` (nu 0.8).
- `src/server/agent/AgentUniverseScan.ts` — `fetchKlines15m(instId, 48)` devine un fetch pe două
  orizonturi (15m pentru micro-structură + 1h pentru regim), iar `computeAgentGridMetrics`
  expune `atrPct1h` și `expectedFirstFillMinutes`.
- Poarta de respingere: se refuză candidatul dacă
  `expectedFirstFillMinutes × 3 > targetHoldingMinutes` (adică nu apuci 3 round-trip-uri).

**Test care trebuie să PICE înainte** — `src/server/engine/grid/__tests__/gridPlan.test.ts`:

```ts
test('geometry: banda nu poate fi mai îngustă decât zgomotul orizontului de holding', () => {
  // 1.6 x ATR15m pe un tape calm => jumatate de banda ~0.8% => stop la ~1.15%
  // => viata medie ~40 min, dar primul fill asteptat ~171 min. Trebuie REFUZAT.
  const geo = deriveGridGeometry({
    atrPct: 0.5,            // ATR(15m)
    atrPct1h: 0.9,
    roundTripFeePct: 0.04,
    targetHoldingHours: 8,
  });
  eq(geo, null, 'o banda sub zgomotul orizontului de holding trebuie refuzata, nu returnata');
});

test('geometry: pe acelasi tape, banda veche de 0.8% ar fi produs un stop la 1.15%', () => {
  // lock-ul de regresie: leaga banda de distanta pana la stop
  const geo = deriveGridGeometry({ atrPct: 0.5, atrPct1h: 0.9, roundTripFeePct: 0.04, targetHoldingHours: 8 })!;
  const stopDistancePct = geo.halfRangePct + 0.15;
  ok(stopDistancePct > 2.5, `stop la ${stopDistancePct}% e in continuare in zona de zgomot`);
});
```

**Criteriu de acceptare:** pe următorii 20 de boți, **durata mediană de viață ≥ 6 h** și
**round-trip-uri mediane per bot ≥ 3**. Azi: 50 min și 1 (61/135 au 0).

**Efort:** M (1–2 zile, atinge geometria partajată între scan și execuție — deci teste de paritate
obligatorii).

**Risc:** capcana din `gridBand.ts` — nu mișca pasul relativ la niveluri, doar lățimea și
amplasarea. Testele de paritate `deriveGridGeometry` ↔ `computeAgentGridMetrics` trebuie să
rămână verzi.

## P0.2 Ieșire pe confirmare, nu pe atingere

**De ce:** audit §7.3. Se închide la 0.15 % dincolo de margine, pe orice wick. 70/89 de opriri
sunt range breakout, iar sistemul nu măsoară dacă breakout-ul a fost real.

**Ce se schimbă:**
- `src/server/engine/grid/gridReasonCodes.ts` + `GridBotAnalyzer.ts` — `rangeBreakoutBufferPct`
  devine proporțional cu ATR (≥ 0.5 % sau 0.5 × ATR15m, care e mai mare) **și** se cere o
  condiție de persistență: prețul integral în afara benzii la `N ≥ 4` evaluări consecutive
  (ex. 4 × 15m = 1 h), sau `efficiencyRatio > 0.45`, sau `ADX > 25` la 3 evaluări.
- `src/server/engine/grid/GridBotAnalyzer.ts` — se adaugă metrica `falseBreakCount` (breakout
  revenit în bandă în < 2 h) și se persistă în evenimentul de stop.

**Test care trebuie să PICE înainte** — `src/server/engine/grid/__tests__/`:

```ts
test('exit: un wick de 15m peste margine NU inchide botul', () => {
  // pretul atinge maxPx + 0.2% pentru un singur evaluari, apoi revine
  const bot = { ...fixture, minPx: 100, maxPx: 102, currentPx: 102.2 };
  eq(decideStop(bot, thresholdsWithPersistence, 1), null, 'un singur tick in afara nu e breakout');
});

test('exit: o rupere sustinuta o ora DA, inchide botul', () => {
  const bot = { ...fixture, minPx: 100, maxPx: 102, currentPx: 103.5 };
  // 5 evaluari consecutive in afara
  eq(decideStop(bot, thresholdsWithPersistence, 5)?.code, 'RANGE_BREAKOUT_CONFIRMED');
});
```

**Criteriu de acceptare:** `falseBreakCount / totalStops` raportat și **< 0.3** pe 20 de boți;
`exitCostUSDT / gridCaptureUSDT < 0.4` (azi `[derivat]` ≈ 1.76).

**Efort:** S–M.

**Atenție la corectitudine:** pe un breakout **real** (cazul INJ din audit §10), oprirea imediată
a fost corectă — grila neutral era short în rally. Confirmarea întârzie stopul cu până la o oră,
deci crește expunerea direcțională. De aceea P0.2 se livrează **împreună** cu P0.3 (contoare) și
se validează în umbră: dacă `exitCost` scade dar `floatPnl` la stop crește mai mult, confirmarea
e prea lentă și `N` trebuie redus.

## P0.3 Separă captura din grilă de costul ieșirii

**De ce:** audit §7.1. Azi `gridProfitUSDT` amestecă +7.53 captură cu ~−13.2 ieșiri într-un
singur număr de −5.70. Nu poți demonstra că round-trip-urile sunt bune.

**Ce se schimbă:**
- `src/server/engine/grid/NeutralGridEngine.ts` — trei contoare:
  `gridCaptureUSDT` (doar `+= netProfit` la arbitraj), `exitCostUSDT` (slippage + diferența de
  preț la închiderea forțată), `feesUSDT`.
  `totalNetPnlUSDT = gridCaptureUSDT + exitCostUSDT − feesUSDT + funding` (identitate păstrată).
- `src/shared/types.ts` — câmpuri noi pe bot + în `OKXFeeTierInfo`-ul deja existent.
- UI: `OKXNativeGridPanel.tsx` — coloane separate, nu un singur „PnL".

**Test care trebuie să PICE înainte:**

```ts
test('accounting: gridCapture si exitCost sunt separabile si suma lor e netul', () => {
  const bot = openBot({ sz: 45, lever: 2, gridNum: 8 });
  fillRoundTrip(bot, { open: 100, close: 100.28, qty: 2 }); // +capture
  forceCloseAtMarket(bot, { mark: 98.5 });                   // -exit
  ok(bot.gridCaptureUSDT > 0, 'captura din round-trip trebuie sa fie pozitiva');
  ok(bot.exitCostUSDT < 0, 'costul iesirii trebuie sa fie negativ si vizibil separat');
  eq(
    round(bot.gridCaptureUSDT + bot.exitCostUSDT - bot.feesUSDT + bot.fundingEstimateUSDT),
    round(bot.totalNetPnlUSDT),
    'identitatea de PnL trebuie sa ramana valida'
  );
});
```

**Criteriu de acceptare:** identitatea de PnL validă pe toate cele 135 de boți istorici după
reprocesare; UI arată cele trei coloane.

**Efort:** S.

**De ce e P0 și nu P2:** fără el, P0.1 și P0.2 nu pot fi evaluate. E instrumentul de măsură al
reparației.

# Gate — rulare de umbră înainte de LIVE

**Obligatoriu înainte de orice revenire pe LIVE.** Sistemul are 7 zile de pierdere continuă și
135 de boți în istoric; nu se rescrie geometria direct pe bani.

- `executionMode = PAPER`, agent `mode = AUTONOMOUS`, **minimum 20 de boți** sau 7 zile.
- Se validează pe date, nu pe impresii:

| Metrică | Prag de trecere | Azi |
|---|---|---|
| Durată mediană de viață | ≥ 6 h | 50 min |
| Round-trip-uri mediane / bot | ≥ 3 | 1 |
| `exitCost / gridCapture` | < 0.4 | ≈ 1.76 `[derivat]` |
| Boți cu 0 arbitraje | < 20 % | 45 % |
| Net cumulat | > 0 | −7.79 |
| `falseBreakCount / stops` | < 0.3 | nemăsurat |

**Dacă pragul de viață trece dar netul rămâne negativ:** problema s-a mutat în sizing (P0.4) și
nu se trece pe LIVE până nu se rezolvă.

## P0.4 Marja per bot vs costul unei ieșiri

**De ce:** audit §4.3. 11.25 USDT/nivel ⇒ 0.031 USDT/round-trip, iar o ieșire la piață costă
0.045–0.09. O ieșire = 2–3 round-trip-uri câștigate.

**Ce se schimbă:** fie `budgetPerBotUSDT ≥ 150`, fie ieșirea devine implicit `stopType 2`
(anulează nivelurile, păstrează poziția cu TP/SL separat) și `stopType 1` doar la confirmare de
trend.

**Test care trebuie să PICE înainte:**

```ts
test('sizing: o iesire la piata nu poate costa mai mult decat 3 round-trip-uri', () => {
  const perLevel = (sz * lever) / gridNum;

```

**Criteriu de acceptare:** testul verde pentru toți boții deschiși ulterior; raport
`exitCost/capturePerTrip` afișat per bot.

**Efort:** S (decizie de config + un guard).

## P1.2 Efficiency ratio: oprește selecția activelor în trend

**De ce:** audit §5.1. `crossingsPerHour = path / step` e mare și în pump — așa au intrat H
(viață 2 min), LINK (6 min), HYPE (4 min), PIEVERSE (−2.25 USDT).

**Ce se schimbă:** `computeAgentGridMetrics` adaugă
`efficiencyRatio = |close[n−1] − close[0]| / pathSum` pe fereastra de ranking.
Se respinge `ER > 0.4`. Se păstrează `crossingsPerHour` doar ca metrică secundară în prompt.

**Test care trebuie să PICE înainte:**

```ts
test('metrics: un pump monoton are crossings mari dar ER mare => respins', () => {
  const m = computeAgentGridMetrics({ price: 100, klines15m: monotonePump(48), roundTripFeePct: 0.04 })!;
  ok(m.crossingsPerHour > 2, 'pump-ul chiar trece de poarta veche de crossings');
  ok(m.efficiencyRatio > 0.4, 'dar ER il demasca');
  eq(scanOne({ klines15m: monotonePump(48) }), null, 'pump-ul nu trebuie sa fie eligibil');
});

test('metrics: un chop real are ER mic si ramane eligibil', () => {
  const m = computeAgentGridMetrics({ price: 100, klines15m: oscillatingKlines(), roundTripFeePct: 0.04 })!;
  ok(m.efficiencyRatio < 0.3);
});
```

**Criteriu de acceptare:** pe următorii 20 de boți, **0 simboluri cu ER > 0.4 la deschidere**;
corelație negativă între ER la deschidere și PnL net (adică metrica prezice).

**Efort:** S.

risc ca și cum ar fi sigur.

**Efort:** S.

## P2.6 Coloană „autoritate" pe fiecare oprire

**De ce:** audit §9.4. Trei surse de stop cu texte diferite, fără marcaj.

# Ce NU se atinge

Din audit §11 — funcționează, nu e de reparat:

- Mecanica round-trip a grilei (`NeutralGridEngine` fill logic). Captura e pozitivă, 227/236
  corecte.
- Guardrail-urile deterministe ca arhitectură (independente de model).
- Gate-ul de environment (`resolveGridEnvGate`) — refuzul implicit la flip LIVE.
- Testele de paritate `deriveGridGeometry` ↔ `computeAgentGridMetrics`.
- Amplasarea benzii (`buildConstructedBand`, `inspectBandLegality`, marja față de extremele 24h).
  Logica e corectă; doar **lățimea** de intrare e greșită.
